07 / Para usar com clareza
O que esperar do kit.
Um método de continuidade baseado em arquivos. A confiabilidade vem do registro útil e da conferência do estado real.

      
Preciso instalar um programa?
Não. O kit contém instruções, modelos e configuração. O agente usa suas ferramentas de arquivos. Este HTML só explica o método; não instala ou executa operações no seu projeto.
A memória é lida sempre, automaticamente?
AGENTS.md orienta a leitura no Codex; CLAUDE.md importa a entrada comum no Claude Code. O comportamento depende da versão, configuração e acesso do agente ao projeto. Se não retomar, peça explicitamente a leitura do AGENTS.md, da skill e de INICIO.md.
Posso usar com outros agentes?
Sim, quando conseguirem ler e editar os arquivos. Use AGENTS.md se suportado ou forneça a orientação explícita. A entrada de Claude Code atende ao CLI e à aba Code do aplicativo, com acesso à pasta; não concede acesso automático a chats comuns.
Posso aproveitar uma memória antiga?
Sim. Preserve o original e produza uma síntese atual com referência à origem. Confira fatos importantes no projeto e diferencie o que foi revalidado do que continua histórico.
Fechei o agente. Tudo foi salvo?
Só o que ele já escreveu nos arquivos. O procedimento pede checkpoints durante tarefas longas e atualização ao concluir etapas, mas não captura o que ficou apenas na conversa após um encerramento abrupto.
O GitHub sincroniza meu trabalho sozinho?
Não. Commit cria uma versão local; push envia a branch; baixar essa branch traz o conteúdo publicado para outro computador. Alterações ainda locais não estarão disponíveis lá. A memória não exige um servidor próprio.
Um teste antigo ainda prova que está tudo certo?
Não. Registre comando, resultado, data e contexto validado. Mudanças posteriores podem exigir nova verificação. Hipótese não é causa confirmada, teste não executado não é teste aprovado e autorização passada não vale para novas alterações.
O guia foi feito a partir de qual versão?
Do kit 0.2.1, README, skill, arquitetura e formatos de registros. Exemplos de tarefas, branches e conteúdo são ilustrativos. Os modelos começam sem repositório definido; o endereço do projeto é informado pelo usuário e guardado em config.json.
